# Ultra-smooth train motion and a Xarxa tab that shows incidents
Objective: markers glide without visible steps or speed jerks; the Xarxa (diagram) tab uses the new icons, draws trains on the line and shows station incidents unmistakably.
Branch: feat/xarxa-incidents (from main) · Delivery: ask-on-risk · Test runner: XCTest; engine and alert code also run locally with Linux `swift test`; screens only on macOS CI and on device.
Status: approved by user 2026-10-30. Delegated to three pi workers with disjoint edit surfaces.

## Specs
- S1 Smooth motion. `LineState` publishes positions at 10 Hz (ticker every 0.1 s, was 1 s: the 8 m hop per second was the visible step). `TrainMotion` becomes velocity based per train: displayed distance `d`, velocity `v >= 0` along the travel direction. Each step `dt`: `ideal` as today (poll position plus engine speed times time since the poll, capped at the segment end); `error = (ideal - d) * dir`; `desiredV = clamp(engineSpeed + 0.1 * error, 0, 12)`; brake before the station: `desiredV = min(desiredV, sqrt(2 * 2 * remaining))` (braking deceleration 2 m/s², half the acceleration limit, so the controller can follow the curve to a smooth stop) with `remaining` = distance still to the segment end; `v` moves toward `desiredV` by at most `4 * dt` (m/s per step: acceleration limit 4 m/s²); `d += dir * v * dt`, never past the segment end, never against the travel direction. New trains snap with `v = engineSpeed`; a gap above 1500 m snaps (kept). Replaces the 24 m/s position clamp.
- S2 Fractional station index. `TrainPositionEngine.stationIndexPosition(atRouteDistance:) -> Double`: position of a route distance expressed in station-order index units (0 = first station, 1.5 = halfway between the second and third), interpolated linearly between station route distances, clamped to 0...(stations - 1). Used by the diagram for a continuous y.
- S3 Incident data. `ServiceAlert` gains `stationCodes: [Int]`, `entranceNames: [String]`, `effectCode: String?` (all with defaults), parsed from the alert `entities` (`station_code` is a string such as "136", `entrance_name` may be absent or "ALL") and `categories.effect_code` (observed: PP2 corridors closed, PP7 access closed, PP8 elevator out, PP9 escalator out). New file `TransportCat/Core/Incidents.swift`:
  `enum IncidentKind: String { case escalator, elevator, accessClosed, other }` and
  `struct StationIncident: Identifiable, Hashable { let id: String; let alertID: String; let kind: IncidentKind; let title: String; let text: String?; let entrance: String? }` and
  `enum IncidentIndex { static func incidents(for alerts: [ServiceAlert], stations: [Station], lineCode: String) -> [Int: [StationIncident]] }`
  keyed by `Station.code`. An alert counts for a line when `lineCodes` contains it; a station matches by code (fallback: normalized name, case- and diacritic-insensitive, only when the alert has no station codes). Kind: PP9 escalator, PP8 elevator, PP7 accessClosed, anything else other. Catalan titles: "Escala mecànica fora de servei", "Ascensor fora de servei", "Accés tancat", "Incidència a l'estació"; for accessClosed with an entrance name append it, e.g. "Accés tancat: Pl. Catalunya". `text` = the first publication's `textCa` stripped of HTML tags (replace `<br>` with a space). Alerts not active now (begin in the future or end in the past) are ignored: take `now: Date = Date()` as a parameter with that default.
- S4 Xarxa incidents. In the diagram a station with incidents is unmistakable: the row has an orange tinted background and an orange left edge, the station marker carries an orange warning badge (`icon-alert`), and under the name one line per incident with its kind icon (`icon-escalator`, `icon-elevator`, `icon-entrance` for accessClosed, `icon-alert` for other) and its title. Above the list, when the line has incidents, an orange summary banner "N incidències a L1" (singular "1 incidència a L1"). Tapping a row opens `StationDetailView`, which lists each incident with its full text.
- S5 Xarxa format. Rows use the line-colored station marker images (`station-<line>`, `terminal-<line>` for the first and last station, 24 pt) on the spine instead of plain circles; each row shows the accessible icon as today and up to two arrival pills, one per direction (toward the last station / toward the first), using `Arrival.via` (1 = toward last, 2 = toward first) and showing the destination name and countdown (e.g. "Fondo 2 min"); a direction without arrivals shows nothing.
- S6 Xarxa trains. Trains are the `train-<line>` image (36x30 pt) drawn ON the spine (the current overlay draws them at the screen center), rotated 90 degrees for forward trains (moving down the list) and -90 for backward ones, at a continuous y from `engine.stationIndexPosition(atRouteDistance: train.routeDistance)` times the row height, plus half a row (row centers). The overlay shares the rows' coordinate space so rows and trains cannot drift apart.
- S7 Icons. `scripts/render-assets.sh` also renders `icon-escalator`, `icon-elevator`, `icon-entrance` (from `statics/icons/escalator.svg`, `elevator.svg`, `station-entrance.svg`) as template imagesets; the asset test covers them.
- S8 No regression. Map, alerts tab, existing text and accessibility labels stay as they are; existing tests keep passing (engine tests updated only where the S1 motion rule changes numbers).

Out of scope: map screen incident badges, interchange data, new endpoints.

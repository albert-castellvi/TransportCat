# Data freshness, incident loading and map/Xarxa UX fixes
Objective: the user always knows how fresh the data is and what is loading; incidents load at launch and refresh; lines without a live feed say so; the map banner, arrival pills and station sheet stop hurting readability.
Branch: feat/freshness-ux (from main) · Delivery: ask-on-risk · Test runner: XCTest; pure Foundation code also runs locally with Linux `swift test`; screens and AppModel on macOS CI and on device.
Status: approved by user 2026-10-30 ("perfecto dale"). Delegated to three pi workers with disjoint edit surfaces.

## Specs
- S1 Alerts at launch and refreshed. `AppModel.startAlertsPolling() async` loads the alerts immediately and then every 60 s until cancelled; `RootView` starts it from a `.task` on the root so every tab has incidents without opening Avisos. `AppModel` publishes `alertsUpdatedAt: Date?` (time of the last successful load); a failed refresh keeps the previous alerts, sets `alertsErrorMessage` and leaves `alertsUpdatedAt` unchanged. The Avisos pull-to-refresh keeps working through `refreshAlerts()`.
- S2 Freshness model. New Foundation-only `TransportCat/Core/Freshness.swift`: `enum DataFreshness: Equatable { case live, delayed, stale, unavailable }` and `enum Freshness { static let delayedAfter: TimeInterval = 30; static let staleAfter: TimeInterval = 90; static func level(lastUpdate: Date?, now: Date, lastAttemptFailed: Bool) -> DataFreshness; static func ageText(since: Date, now: Date) -> String }`. Rules: no `lastUpdate` -> `.unavailable`; age < 30 s -> `.live`; 30...<90 s -> `.delayed`; >= 90 s -> `.stale`; a failed last attempt downgrades `.live` to `.delayed` (never upgrades). `ageText`: under 5 s "ara mateix", under 60 s "fa N s", under 3600 s "fa N min", otherwise "fa N h" (integer division, negative ages count as 0).
- S3 Line and alert state. `LineState` gains `private(set) var arrivalsUpdatedAt: Date?` (last successful poll), `private(set) var lastPollFailed = false`, `private(set) var isFeedEmpty = false` (a successful poll whose response holds no arrivals at all for the line: L9N, L9S, L10N, L10S and FM today; TMB publishes no live data or timetable for them, verified 2026-10-30) and `func freshness(now: Date = Date()) -> DataFreshness`. `AppModel` gains `func activeAlerts(affecting lineCode: String, now: Date = Date()) -> [ServiceAlert]` (alerts of the line that are active now, S5).
- S4 Telemetry. Each arrivals poll and each alerts refresh adds a Sentry breadcrumb (category `poll`, data: line or "alerts", `latency_ms`, `ok`, counts: arrivals and trains, or alerts). A feed that is empty (S3) adds a breadcrumb `feed empty`. No new Sentry events: transient network failures stay unreported as today.
- S5 Alert semantics. `ServiceAlert` gains `effectType: String?` (from `categories.effect_type`: observed TRAFFIC for service interruptions, INFRASTRUCTURE for facilities), `func isActive(now: Date) -> Bool` (same rule as `IncidentIndex`: began or no begin date, not ended or no end date) and `var severity: AlertSeverity` where `enum AlertSeverity: Int, Comparable { case facility = 0, service = 1 }` (service when `effectType == "TRAFFIC"`). `IncidentIndex` uses `isActive`. For incidents of kind `other`, `title` becomes the first sentence of the alert text (cut at the first ". " or at 70 characters with an ellipsis), falling back to "Incidència a l'estació".
- S6 Readable pills. New Foundation-only `TransportCat/Core/HexLuminance.swift`: `enum HexLuminance { static func isLight(_ hex: String) -> Bool }` using sRGB relative luminance, light when above 0.5. The arrival pills in Xarxa become a capsule filled with the line color with black text when the color is light and white text otherwise (was line color on a 15 % tint, unreadable for L1/L2/L5 in dark mode).
- S7 Freshness and incident chips. New `FreshnessChip` (SwiftUI): a capsule "● En directe · fa 12 s" (green dot), "● Amb retard · fa 45 s" (amber), "● Dades antigues · fa 2 min" (red), "● Sense dades" (gray); the age updates every second (`TimelineView`). Shown under the line picker on the map and in Xarxa for the selected line, from `LineState.freshness`. New `IncidentsChip`: shows "Actualitzant incidències…" with a spinner while the first alert load has not finished, otherwise, if the line has active alerts, "⚠ N incidències" (orange when the highest severity is facility, red when service); tapping it opens a sheet listing each alert (`icon-alert`, text, validity dates when present, and "Actualitzat <ageText>" in the header from `alertsUpdatedAt`). Nothing is shown when there are no active alerts. It replaces the big red `AlertBanner` on the map (the file stays, unused). Xarxa keeps its orange summary banner and gets both chips above it.
- S8 No live data. When `LineState.isFeedEmpty` the map and Xarxa show a clear notice instead of an empty screen: icon `icon-realtime-off` (from `statics/icons/realtime-unavailable.svg`) and "Sense dades en temps real" with "TMB no publica les arribades d'aquesta línia." The station sheet text mentions the same. The chip shows `.unavailable`-style "Sense dades en temps real" instead of a fake "En directe".
- S9 Station sheet. The incident text is no longer clipped under the navigation bar (video of build 23); the sheet can expand (`.presentationDetents([.medium, .large])`).
- S10 No regression. Existing behavior, text and accessibility labels not named above stay; existing tests keep passing.

Out of scope: schedule-based train estimation, notifications, new endpoints, FM funicular specifics.
